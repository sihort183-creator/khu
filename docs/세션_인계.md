## 3. 반드시 알아야 할 함정

### 3.1 절대 넘지 말 것 — DB 연결
Supabase 풀러가 **사용자당 15개**로 막는다. `SHOW max_connections` 의 60은 서버 값이라 무의미하다.
실제 연결 수 = `KHU_SOURCE_CONCURRENCY` + 4. **11을 넘기면 수집이 통째로 죽는다.**
2026-09-07 24로 올렸다가 6분 만에 실패해 30분 넘게 멈췄다.

### 3.2 설정은 새 작업부터 적용된다
저장소 변수는 **작업이 시작할 때 값이 굳는다.** 도는 중에 바꿔도 그 작업에는 안 들어간다.
초기 실행기는 4.5시간까지 돌므로 반영이 몇 시간 뒤일 수 있다. 이것 때문에 몇 번 헷갈렸다.

### 3.3 수집을 방해하지 않는다
실행 중인 Actions 수집을 취소하지 않는다. 서브에이전트에도 매번 금지시킨다.
날짜 정렬 검증(`app.ops.date_order`)은 절대 다시 돌리지 않는다 — 커서를 1로 되감아 수집을 멈춘다.

### 3.4 조직 식별자는 이름 경로의 해시다
상위를 새로 채우면 식별자가 바뀌어 **공지가 고아가 된다.** `sources_sync` 에 예전 식별자로
기존 행을 찾는 장치가 들어 있다. 건드리지 마라. 반영 전후로 `organizations` 행 수가
**484 그대로인지 반드시 확인**한다.

### 3.5 `sources_sync` 는 기존 행의 status 를 바꾸지 않는다
등록부가 active 라고 해도 DB 가 pending 이면 그대로다. **46곳이 이 구멍에 걸려 있다.**
아직 안 고쳤다.
