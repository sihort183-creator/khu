# 날짜 경계와 변경분 내보내기 수정 결과

## 범위와 완료 기준

사용자가 지적한 두 문제는 운영 날짜 경계가 활성화되지 않은 점과 공개 때마다 변경 없는 전체 파일을 다시 올리는 점이다. 코드 검사 통과와 운영 적용·실측을 구분한다. 이 문서의 운영 결과는 검증 후 갱신한다.

## 날짜 경계

- 운영 정본인 출처 설정 이력과 수집기의 실제 요청 경로를 연결한다.
- 공식 게시판 목록 전체를 읽고 고정 공지를 분리하여 날짜 확정·날짜 순서·끝 페이지 도달을 검증한다. 일부 앞쪽 표본만으로 전체를 날짜순이라고 설정하지 않는다.
- 공통 게시판에서 제공하는 최대 50개 표시를 사용하고, 그누보드는 게시일 내림차순 요청을 사용한다. 실제 응답 검증을 통과한 설정만 새 버전으로 적용한다.
- 검증 증거에는 원문 해시·관찰 시각·페이지·항목 수를 기록한다. 이번 초기 수집용 검증은 12시간 유효하며, 만료되면 날짜 조기 종료를 사용하지 않는다.
- 날짜가 없거나 순서가 뒤집힌 원문을 만나면 검증 가정을 폐기하고 전체 탐색을 계속한다. 기간 밖 고정 공지와 날짜 미확정 글을 일괄 버리지 않는다.
- 페이지 크기나 정렬이 바뀐 출처는 기존 페이지 위치와 완료 표시를 재검증한다. 추가 발견한 10쪽 묶음의 마지막 페이지 오판도 수정하고 영향을 받을 수 있는 완료 출처를 재검증한다.

## 변경분 내보내기

- 공개 데이터 내용의 해시를 객체 주소로 사용하여 같은 내용은 재업로드하지 않는다.
- 공개 버전별 참조 목록이 필요한 객체를 가리킨다. 조회 서버는 기존 주소에서 해당 버전의 생성 시각·개정·신선도를 복원한다.
- 공지 상세뿐 아니라 연락처·목록·색인·사전·조직도 변경이 없으면 재사용한다.
- 업로드 순서는 내용 객체 → 개정 참조 목록 → 최신 포인터 → 공개 상태다. 참조 목록 생성 실패가 기존 공개를 바꾸지 않도록 검사한다.
- 숨김·삭제·병합으로 빠진 공지는 새 개정에서 참조하지 않는다. 내용 객체와 참조 목록은 조회 서버를 통한 직접 접근을 차단한다.
- 오래된 개정을 정리할 때 현재 공개 개정을 보존한다. 동시 재사용 중인 내용 객체를 삭제하지 않도록 공유 객체 자동 삭제는 보류했다. 장기 저장 공간 회수에는 전체 쓰기 잠금 또는 별도 안전한 정리 절차가 필요하다.

## 검사 및 운영 측정

로컬 재현 검사에서 동일 데이터의 두 번째 공개는 내용 파일 재업로드 없이 참조 목록·최신 포인터·상태 3개만 업로드했다. 신선도만 바뀐 사례는 출처 파일까지 포함해 4개였다. 이 수치는 검사 데이터의 업로드 개수이며 운영 시간 보장을 뜻하지 않는다.

실제 운영은 조회 서버를 먼저 배포해 기존 개정 호환을 확인한 다음 새 내보내기를 사용한다. 수집과 공개 실측은 동일 실행 그룹으로 직렬화한다. 처음 전환할 때는 내용 객체를 최초 생성하므로 전체 업로드가 필요하며, 두 번째 공개에서 재사용 개수와 시간을 측정한다.

## 사용자 요청에 따른 마무리와 남은 작업

2026-09-07 마무리 시점에 추가 구현을 중단하고 현재 변경을 커밋한다. 이미 승인되어 실행 중인 원격 검증·공개 실측과 그 뒤에 대기 중인 연속 수집은 유지한다. 이 문서 작성 이후의 실행 결과를 확인했다고 간주하지 않는다.

마지막 운영 조회: 대상 설정 370개 중 날짜 경계 활성화 0개, 날짜 경계 종료 기록 0개다. 전체 원문 감사가 아직 진행 중이며 감사 종료 후 설정 적용 단계가 실행된다. 코드 배포와 운영 날짜 경계 검증 완료는 구분한다.

등록된 수집 대상 370개 중 범위 완료 표시는 62개, 진행 중 179개, 미시작 126개, 목록 경계 도달 후 상세 대기 3개였다. 이 완료 표시는 새 정렬 검증 적용에 따른 재검증 전 수치다. 저장 원문은 4,866개, 상세 오류 대기는 231개다. 공개 공지 건수나 전체 누락 해소 건수와 같지 않다.

남은 작업은 다음 순서로 확인한다.

1. 운영 검증 실행의 최종 결과와 원문 산출물을 확인한다. 통과·역전·날짜 미상·접근 실패·페이지 상한 출처를 집계하고 실제 적용된 설정 수를 DB에서 대조한다. 이후 새 수집에서 날짜 경계 종료 기록이 생성되는지 확인한다.
2. 연속 두 번 공개의 첫 전환 시간과 두 번째 재사용 시간·업로드 수를 기록한다. 운영 1분 미만은 아직 확인하지 않았다. 새 공개 개정의 목록·상세·색인·연락처를 실제 조회하고 캐시 응답도 확인한다.
3. 대기 중인 연속 수집이 실제 시작되는지 확인하고 초기 범위와 필수 상세 미해결을 추적한다. 오전 8시 도달만으로 미완료를 완료 표시하지 않는다. 12시간 검증 유효기간을 넘겨 초기 범위를 다시 수집해야 한다면 정렬 근거를 갱신해야 한다.
4. 상세 대기 231개는 비공개·로그인 필요와 추출 오류를 원문 기준으로 구별한다. 클로드의 도서관·현장실습 추출기, 미분류 게시판 판정 결과를 검토·통합한다. 기존 삭제 후보 복구도 별도 검증이 필요하다.
5. 공유 내용 객체의 장기 정리 방식과 프런트엔드 운영 주소·도메인 연결·실제 서비스 화면 검증은 남아 있다.

따라서 현재 완료한 범위는 두 수정의 구현·자동 검사·조회 서버 배포와 운영 검증 시작이다. 운영 적용 성공·1분 미만 실측·초기 전체 수집 완료는 아직 완료로 보고하지 않는다.
