# 수집 대상은 어떻게 정하는가

2026-09-06 에 수집 대상을 처음부터 다시 조사하면서 정한 방법과, 그렇게 정한 이유를 적는다.
다음 학기에 다시 조사할 사람이 같은 함정에 빠지지 않도록 **무엇이 틀렸는지**를 함께 남긴다.

## 한 줄 요약

게시판 **이름**으로 공지를 고르지 않는다. 학교가 공개한 **사이트 명부**에서 출발해,
게시판의 **상위 메뉴**와 **최근 글**로 성격을 판정한다. 판정은 학기마다 한 번 갱신한다.

## 왜 다시 조사했나

처음 만든 조사 도구는 게시판을 250개 찾았다. 실제로는 2,335개였다. 세 가지가 겹쳐 있었다.

1. **호스트 이름을 손으로 추측했다.** 49개를 적어 두었는데 `bio`·`dent`·`art`·`civil`·`applied`
   처럼 실재하지 않는 이름이 절반 가까이였다. 진짜 이름은 `biology`·`dental`·`khuart`
   ·`civileng`·`applsci` 다.
2. **첫 화면에 걸린 링크만 봤다.** 메뉴 안쪽 게시판은 통째로 빠졌다.
3. **게시판 종류를 한 가지만 알았다.** 공통 CMS 형식만 찾아서, 그누보드를 쓰는
   법학전문대학원·미래인재센터·의과대학 같은 곳이 "게시판 없음"으로 처리됐다.

## 방법

### 1단계 — 사이트 명부 (`discover_sites.py` → `sites.json`)

경희대 CMS 는 사이트 가이드에서 학교가 관리하는 전체 사이트 목록을 JSON 으로 돌려준다.
도메인을 추측하는 대신 이 명부를 정본으로 삼는다. 사이트 173개, 도메인 123개.

응답에는 담당자 이메일과 외부 서비스 키가 섞여 있다. **저장소에는 남기지 않는다.**

### 2단계 — 호스트 확정 (`discover_hosts.py` → `hosts.json`)

명부에도 빠짐이 있다. 국제처는 명부에 `oiak.khu.ac.kr` 로 적혀 있지만 실제 사이트는
`oia.khu.ac.kr` 에 있다. 명부만 믿으면 국제처 공지가 통째로 빠진다.

그래서 명부의 사이트들이 서로 링크한 `*.khu.ac.kr` 주소를 모아 실제로 열어 본다.
이렇게 해서 취업(`goodjob`)·학사(`ghaksa`/`shaksa`)·의과대학(`khusm`)·법학전문대학원(`law`)
처럼 공지가 가장 많이 올라오는 곳들이 들어왔다. 호스트 246개 중 수집 대상 160개.

각 호스트의 게시판 엔진을 확인해 어댑터를 정한다. `khu_board` 142곳, `gnuboard` 18곳.

### 3단계 — 게시판 탐색 (`discover_sources.py` → `discovered.json`)

첫 화면이 아니라 **메뉴를 너비 우선으로 따라간다.** 게시판 목록 화면과 내용 화면 모두
사이트 메뉴를 그대로 달고 있어서, 어느 쪽을 열든 나머지 메뉴가 따라온다.
게시판 2,808개를 찾았고 그중 2,335개가 글이 있는 게시판이다.

### 4단계 — 게시판 성격 판정 (`profile_boards.py` → `board_profiles.json`)

**이 단계가 이번 조사의 핵심이다.** 판정 순서는 다음과 같고, 게시판 이름은 쓰지 않는다.

1. **게시판 종류(`board_code`)** — 교수 명단·영상·연구실 소개처럼 공지가 올라올 수 없는
   종류를 먼저 뺀다. 원문을 열지 않아도 된다.
2. **상위 메뉴** — 게시판이 `Announcement`·`공지사항` 아래 묶여 있으면 이름과 무관하게
   공지로 본다. 메뉴 트리에서 조상 항목을 거슬러 올라가 알아낸다.
3. **최근 글** — 제목과 날짜로 실제로 무엇이 올라오는지 본다.

#### 이름으로 고르면 안 되는 이유

국제처(`oia`)가 그 근거다. 같은 사이트, 같은 게시판 종류인데 내용이 갈린다.

| 게시판 | 판정 | 근거 |
| --- | --- | --- |
| `Outgoing Program` | 공지 | 상위 메뉴가 `Announcement`. 마감이 있는 교환학생 모집 공고가 올라온다 |
| `Partner University Program` | 공지 | 상위 메뉴가 `Announcement` |
| `News` | 소식 | 행사 후기와 사진뿐이다 |
| `Incoming Program` | 휴면 | 마지막 글이 2023-11 |

이름만 보면 `Notice` 하나만 골랐을 것이고, 마감이 있는 모집 공고를 놓쳤을 것이다.

#### 커뮤니티·자료실은 자동으로 넘기지도 버리지도 않는다

`커뮤니티` 아래에 공지사항이 들어 있는 곳이 많다. 그래서 상위 메뉴가 커뮤니티라는 이유만으로
공지로 인정하지 않고, 동시에 버리지도 않는다. 최근 글을 보고 정한다.

#### 판정 결과 (2026-09-06)

게시판 2,335개 → 공지 804 · 휴면 503 · 제외 479 · 자료 283 · 소식 144 · 미정 90 · 빈 게시판 32.

소식(시상·협약·후기·사진)은 수집하지 않기로 했다.

#### 규칙을 고칠 때 원문을 다시 받지 않는다

`--reclassify` 는 이미 저장해 둔 표본으로 판정만 다시 한다. 요청이 한 번도 나가지 않는다.
실제로 아래 세 가지 결함을 이 방식으로 요청 0건에 고쳤다.

- `취업정보` 게시판이 미정으로 빠졌다. 판정 낱말에 `채용` 이 없었다.
- `자료실`·`발표 자료`·`안내 책자`·`기출 문제` 가 공지로 들어왔다.
  제목의 "안내" 를 공지 신호로 쓴 것이 원인이라, "안내" 말고 다른 신호가 없으면 공지로 보지 않는다.
- `학술대회 > 발표 자료` 가 행사 공지로 걸렸다. 자료 게시판 규칙을 행사 규칙보다 앞에 두었다.

### 5단계 — 등록부 생성 (`build_registry.py` → `organizations.json`, `sources.json`)

공지로 판정된 게시판만 출처로 만든다.

- **조직 이름은 지어내지 않는다.** 사이트 명부의 사이트 이름을 쓰고, 명부에 없으면 페이지 제목을
  쓴다. 둘 다 없으면 `needs_review` 로 남긴다.
- **조직은 호스트가 아니라 사이트 ID 로 정한다.** 한 호스트에 다른 사이트의 게시판이 걸려 있는
  경우가 있어서, 호스트로 정하면 소속이 틀린다.
- **같은 게시판이 여러 호스트에 걸린다.** 호텔관광대학 게시판(`hot20_kor`)은 10개 학과
  사이트에서 같은 내용으로 열린다. 합치지 않으면 같은 공지를 열 번 수집한다.
  사이트 명부가 가리키는 원래 도메인을 대표로 삼아 합친다. 이번에 354개를 합쳤다.
- **대상 범위 기본값은 출처의 소속 조직이다.** 본부 게시판을 전교생 대상으로 단정하지 않는다.

결과: 조직 121개, 출처 450개(`active` 405 · `pending` 45).
판정 근거가 뚜렷한 것만 `active` 로 두고 나머지는 운영자가 승격한다.

## 다시 조사하는 주기

**학기마다 한 번이면 된다.** 게시판 성격은 학기 중에 바뀌지 않는다.
새 학기가 시작되면 아래를 순서대로 돌린다.

```bash
python scripts/discover_sites.py --out registry/bootstrap/sites.json
python scripts/discover_hosts.py --out registry/bootstrap/hosts.json
python scripts/discover_sources.py --out registry/bootstrap/discovered.json
python scripts/profile_boards.py --out registry/bootstrap/board_profiles.json
python scripts/build_registry.py
```

`sites.json`·`hosts.json`·`board_profiles.json` 에는 조사 시점과 재조사 주기가 적혀 있다.

## 통신량

조사는 가볍지 않다. 경희대 서버는 압축을 하지 않아(`Accept-Encoding: gzip` 을 보내도
`Content-Encoding` 이 없다) 페이지 하나가 평균 87KB 다.

| 단계 | 요청 | 내려받은 양 |
| --- | ---: | ---: |
| 게시판 탐색(160개 호스트) | 8,798 페이지 | 약 747MB |
| 게시판 성격 조사(2,335개) | 2,335 페이지 | 약 200MB |

측정 기기의 통신을 그대로 쓰므로, 데이터 요금이 있는 회선에서는 돌리기 전에 확인한다.
판정 규칙만 고칠 때는 `--reclassify` 를 써서 통신을 하지 않는다.

## 아직 남은 것

- 게시판 9곳이 페이지 예산(200)에 걸려 더 남아 있다.
- 미정 90개는 연구 성과·명단 계열이 대부분이라 대체로 버려도 되지만 확인하지 않았다.
- 휴면 503개는 학기가 시작되면 되살아나는 것이 있을 수 있다. 다음 조사에서 다시 판정된다.
- 중앙도서관(`lib`)과 현장실습(`intern`)은 두 어댑터 중 어느 것도 맞지 않아 빠져 있다.
