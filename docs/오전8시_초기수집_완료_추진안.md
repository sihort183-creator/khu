## 구현 및 운영 확인

출처 작업과 주소 조회의 실행 자원을 분리하고, DB 세션은 출처 작업 안에서 독립 생성한다. 통신은 중앙 클라이언트를 공유하므로 같은 호스트의 요청 제한을 유지한다. 초기 미완료 출처는 정상 60분 간격을 기다리지 않으며 실패 재시도 대기는 유지한다. 기존 글·대상 정보 조회는 묶고 일반 기존 글의 불필요한 상세 재확인은 미룬다.

초기 실행기는 수집 예산 5분의 회차를 연속 수행한다. 회차 정리·진행 저장 시간만큼 실제 회차는 더 길 수 있다. 중복 비교와 전체 공개는 약 60분마다 회차 사이에 수행한다. 실행 서버의 시간 제한 전에 작업을 끝내고 후속 실행을 자동 요청한다. 한국 시각 2026-09-07 08:00 종료 설정을 운영 저장소에 적용했다. 최종 공개에 15분을 남기고 초기 집중 회차를 멈춘다. 먼저 모두 완료하면 다음 실행부터 즉시 유지 수집을 수행한다.

구현 개정 `86942e4`의 자동 검사와 운영 시험이 통과했다. 시험에서는 실제 선택 대상 2곳을 처리해 94초 동안 원문 37회 요청, 새 공지 5건 저장, 상세 실패 0건을 확인했다. 두 출처 처리 시간은 각각 약 87초와 25초다. 이전 시험과 대상·기존 데이터 비율·공개 여부가 달라 단순 가속 배수로 비교하지 않는다. 전체 범위 완료를 의미하지 않는다.

클로드에 넘길 독립 작업은 [클로드 공지수집 가속 작업지시서](클로드_공지수집_가속_작업지시서.md)에 정리했다. 아래는 최초 설계와 판정 기준이며, 아직 실측하지 않은 동시 처리 24개 등의 제안은 적용한 설정이 아니다.

23:19 조회 시점에 실행 중인 GitHub 수집 작업은 없었다. 예약 활성화와 실제 연속 가동은 다르다. 미완료 작업을 예약 시각만 기다리게 두면 안 된다.

## 오늘 밤 권장 경로

새 분산 시스템을 전면 도입하기보다 기존 수집·정규화·저장 규칙을 재사용한다. 아래 변경을 하나의 초기 수집 전용 실행 경로로 묶고 소수 출처 검사를 통과한 뒤 확대한다.

1. **연속 초기 수집**: 미완료 출처는 정기 확인 간격과 별도로 바로 다시 작업할 수 있게 한다. 실패의 다음 재시도 시각은 지킨다. 작업마다 마지막 확정 위치를 저장하고 출처를 공평하게 순환한다.
2. **독립 실행 단계**: 초기 수집 작업은 원문 확보·증거 보관·DB 저장까지만 처리한다. 전체 공개 파일 생성은 별도 실행하고 중복 공개가 겹치지 않게 단일 실행으로 제한한다. 최신 확인도 초기 작업과 같은 출처를 동시에 수정하지 않게 소유권을 관리한다.
3. **기존 원문 묶음 확인**: 목록의 원문 번호를 한 번에 조회해 빠진 상세부터 요청한다. 기존 글의 일반 재검사는 뒤로 보내되 실패 글·중요 변경·진행 중 고정 공지를 무기한 제외하지 않는다.
4. **통신·저장 겹쳐 수행**: DB와 주소 조회가 모든 비동기 작업을 막지 않도록 분리한다. DB 세션을 여러 스레드가 공유하지 않는다. 다운로드 완료 후 제한된 저장 작업자로 넘기고 저장 대기열 크기에 상한을 둔다.
5. **동시 수 조정**: 현재 12개와 비교할 후보로 전체 24개를 시험한다. 같은 실제 서버는 기본 동시 1개를 유지하고 응답 시간·오류율·공유 서버 관계가 확인된 곳만 2개로 시험한다. DB 연결을 다운로드 작업자 수만큼 늘리지 않는다. 수치는 확정 최적값이 아니라 실측 후보다.
6. **목록 경계 효율화**: 정렬이 확인된 게시판은 3월 경계에서 종료한다. 확인되지 않은 게시판을 일괄 날짜순으로 지정하지 않는다. 공식 피드·목록 응답·페이지당 건수 확대가 가능한지는 해당 원문에서 확인하고 동일 식별자 집합이 나오는 경우만 채택한다.

초기 수집 중 공개는 60분 단위 묶음을 제안한다. 이것은 수집을 60분 쉬게 하자는 뜻이 아니다. 수집은 계속 진행하며 최종 공개는 별도로 실행한다. 연락처처럼 변하지 않은 자료를 재사용하려면 같은 개정의 참조가 유지되도록 해야 한다.
