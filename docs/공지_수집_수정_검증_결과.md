# 공지 수집 수정 및 검증 결과

- 작성일: 2026-09-06
- 범위: 수정 계획 실행본을 검토하면서 발견한 8개 결함과 연결된 저장·조회 경로 보완
- 적용 위치: 로컬 작업 폴더. 운영 배포와 운영 데이터 변경은 수행하지 않았다.

후속 운영 반영: 이 문서는 배포 전 검사 기록이다. 이후 승인된 배포·DB 구조 변경과 실제 운영 검증 결과는 [운영 배포 결과](운영_배포_DB_변경_결과.md)에 기록했다.

## 연결된 저장·성능 보완

- 초기 시작일 기본값은 2026-03-01이다. 시작일 변경 시 기존 완료와 재개 상태를 재평가한다.
- 원문 번호로 미발견을 판정하며, 첫 페이지부터 실제 게시판 끝까지 확인한 경우에만 삭제 판정을 수행한다. 날짜 경계·페이지 상한·시간 소진은 삭제 근거가 아니다.
- 재발견 시 내용 변경이 없어도 자동 삭제 상태를 복구한다. 운영자가 숨긴 공지는 복구하지 않는다.
- 실패 대기 시간을 지키고 최근·고정·진행 중 공지는 일 단위, 오래된 원문은 회전 재점검한다. 첨부와 게시일 변경도 저장한다.
- 원문 증거 저장 실패는 상세 실패로 남겨 재시도한다. 같은 내용의 증거를 매번 다시 업로드하지 않으며 객체 저장 통신은 별도 실행 스레드로 보낸다.
- 실제 실행에서는 원문 통신 전 저장을 확정해 데이터베이스 연결을 반환한다. 완료 페이지를 중간 저장하고 예상하지 못한 오류는 해당 출처 실패로 기록한다.
- 출처별 기본 시간 몫은 120초다. 전체 남은 시간보다 길게 배정하지 않으며 오래 확인하지 않은 출처부터 처리한다. 개별 통신의 제한 시간까지 즉시 취소하는 강제 제한은 아니다.
- 내보내기 관계 자료를 묶어서 조회한다. 검색의 8,000건 절단을 제거하고 2,000건 단위 색인 조각을 만든다. 소비자는 같은 개정의 조각과 건수를 검사하며 일부 파일 실패를 빈 검색 결과로 처리하지 않는다.
- 실제 상세 응답의 원문·첨부·연락처 언급 구조를 화면이 읽는 구조로 변환한다.
- 실행 종료를 기록한 뒤 공개 상태를 다시 생성한다.

## 저장 구조 변경과 적용 순서

저장 구조 버전 `0002`는 과거 수집의 재개 위치·기준 원문·도달 상태·오류·실행 결과와 상세 재시도 정보를 추가한다. 새 데이터베이스 구성과 기존 버전에서의 상승·하강·재상승을 임시 데이터베이스에서 검사한다. 운영 이행을 수행했다는 의미는 아니다.

실제 반영 시에는 운영 상태 보존 → 저장 구조 변경 → 새 정적 색인 계약을 읽는 화면 배포 → 수집·내보내기 배포 → 제한된 출처 재수집 → 원문·저장·공개·화면 대조 순서가 필요하다. 이전 화면은 분할 색인을 읽지 못하므로 새 내보내기를 먼저 운영에 적용하지 않는다.

## 남은 운영 작업과 원래 계획의 별도 항목

- 운영 배포 버전·실제 저장 구조·공개 개정 대조, 운영 데이터 이행, 과거 재수집과 삭제 피해 후보 복구는 미수행이다.
- 수정 전후 실제 수집 시간·원문 요청량·최신 반영 지연·전체 대상 누락 건수는 측정하지 않았다. 속도가 몇 배 향상됐다는 주장을 하지 않는다.
- 실제 브라우저와 운영 저장소·캐시를 통한 사용자 결과 검증은 별도로 필요하다.
- 도서관·현장실습 전용 추출기, 미정 게시판·탐색 미완료 호스트·휴면 게시판 재조사, 주소 변환망 처리, 만료 첨부 주소, 실행 소유권·생존 신호는 이번 8개 검토 결함 수정에 포함되지 않았다. 원래 계획 전체가 완료된 상태는 아니다.
