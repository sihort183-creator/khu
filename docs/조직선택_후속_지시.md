# 조직 선택 화면 — 후속 지시

사용자가 작업 중인 화면을 보고 직접 지적한 것과, 그 지적을 확인하다 찾아낸 데이터 문제를 적는다.
**앞선 조직 선택 UI 작업이 끝난 뒤 이어서 한다.** 사용자는 개발자가 아니고 화면으로 판단한다.

작성 시점: 2026-09-07 02:30 KST.

---

## 1. 사용자 지적 (그대로 옮긴다)

> "경희대학교 국제/서울 해서 경희대 전체 공지를 못 보잖아. 이것도 조직에 넣었어야지."

> "지금 이렇게 면으로 들어오는 디자인 마음에 안 든다. 정정하라고."

두 번째는 조직 목록 맨 위 "경희대학교 전체 / 모든 공지" 항목을 **빨간 테두리 상자(면)** 로 처리한 것을
가리킨다. 화면 안에서 그 항목만 튀는 덩어리로 들어온다.

## 2. 지적을 확인하다 찾은 진짜 원인 — 캠퍼스 매핑이 사실상 없다

운영 DB 실측(2026-09-07 02:30):

| 항목 | 값 |
| --- | --- |
| 조직 총수 | 484 |
| **캠퍼스에 안 묶인 조직** | **477 (98%)** |
| 캠퍼스에 묶인 조직 | 서울 5, 국제 2 |
| 캠퍼스로 걸러 나오는 공지 | 서울 288, 국제 46 |
| **캠퍼스에 안 묶인 출처의 공지** | **7,677** |

`organization_campuses` 매핑이 7건뿐이다. 그래서 **캠퍼스를 고르는 순간 공지의 98%가 잘려 나간다.**
사용자가 "서울캠퍼스 전체 20건"만 본 이유가 이것이다. UI 문제 이전에 필터가 자료를 죽이고 있다.

## 3. 해야 할 일

### 3.1 캠퍼스가 공지를 잘라내지 않게 한다 (가장 중요)

- **캠퍼스에 안 묶인 출처의 공지가 사라지면 안 된다.** 매핑이 없다는 것은 "그 캠퍼스가 아니다"가
  아니라 "아직 모른다"는 뜻이다. 모른다는 이유로 감추지 않는다.
- **"경희대학교 전체"는 캠퍼스 선택과 무관하게 모든 공지를 보여야 한다.** 국제·서울을 합친 것이
  아니라, 캠퍼스를 모르는 것까지 포함한 전부다.
- 캠퍼스 선택은 **좁히는 수단**이지 **들어가는 문**이 아니어야 한다. 고르지 않아도 전체가 보인다.

### 3.2 디자인 — 면으로 튀지 않게

- 그 항목만 테두리·배경으로 덩어리를 만들지 않는다. 목록의 다른 항목과 같은 결로 두되,
  맨 위에 있다는 것과 선택됐다는 것만 최소한으로 드러낸다.
- 강조가 필요하면 색 면이 아니라 **글자 굵기·위치·구분선** 같은 가벼운 수단을 쓴다.
- `docs/KHU_UI_BRAND_GUIDE.md` 의 색과 간격을 따른다. 새로 만들지 않는다.

### 3.3 확인

- 모바일 375px 과 데스크톱 둘 다에서 본다.
- **실제 배포된 화면 기준으로 판단한다**: `https://khu-notice-web.khu-notice-sihort.workers.dev`
  (로컬은 `.claude/launch.json` 의 `frontend`).
- "경희대학교 전체"를 눌렀을 때 나오는 공지 수가 캠퍼스를 골랐을 때보다 **훨씬 많아야** 정상이다.
  비슷하면 3.1 이 안 고쳐진 것이다.
- `npm run lint`, `npx tsc --noEmit`, `npm run build` 를 모두 통과시킨다.

## 4. 별도로 남는 것 (이 작업 범위 밖)

`organization_campuses` 매핑 477건이 비어 있는 것 자체는 수집·등록부 쪽 과제다. 화면에서
안 잘리게 막는 것과 별개로, 나중에 조직마다 캠퍼스를 채워 넣어야 캠퍼스 필터가 제 구실을 한다.
