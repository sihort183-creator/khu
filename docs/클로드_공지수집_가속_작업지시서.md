# 클로드 작업지시서 — 공지 수집 예외 해결

이 문서 전체를 클로드에 전달한다. 목표는 2026-09-07 오전 8시 초기 수집 완료와 정오 서비스 공개 준비다. 일반 공지 다운로드·DB 저장·초기/유지 실행 전환은 Codex가 담당한다. 클로드는 자동 수집에서 빠지는 출처와 추출 오류를 해결한다.

## 작업 폴더와 협업 경계

작업 폴더: `C:\Users\박시형\Desktop\경희공지`.

다른 작업자가 같은 저장소에서 작업 중이다. 기존 변경을 되돌리거나 전체 파일을 과거 버전으로 덮어쓰지 않는다. 우선 현재 작업 상태와 원문 지침을 읽는다. 비밀 설정·DB 연결 문자열·토큰 파일을 답변이나 도구 출력에 포함하지 않는다.

**클로드 수정 가능 범위**

- 새 전용 추출기: `backend/app/ingestion/library.py`, `internship.py`
- 전용 검사: `backend/tests/test_adapter_library.py`, `test_adapter_internship.py`
- 공개 원문 표본: `backend/tests/fixtures/library/`, `internship/`
- 조사 보고서: `docs/클로드_수집예외_조사결과.md`
- 제안 자료: `registry/proposals/` 아래 새 파일

**Codex가 수정 중인 파일**: `backend/app/run/`, `backend/app/storage/`, `backend/app/config.py`, `backend/app/ingestion/http.py`, `.github/workflows/`. 이 경로는 수정하지 않는다. 기존 공통 추출기나 추출기 등록 파일 `backend/app/ingestion/__init__.py`를 바꿔야 하면 이유와 정확한 패치를 보고서에 제안한다.

등록부 원본 `registry/bootstrap/`도 직접 덮어쓰지 않는다. 신규·변경·통합 제안을 별도 파일로 제출한다. 운영 DB 변경, 출처 일괄 활성화, 커밋·푸시·배포·수집 예약 변경은 하지 않는다. Codex가 검토·통합한다.

## 우선순위 1 — 미지원 출처에서 실제 공지를 가져오기

대상은 `lib.khu.ac.kr` 도서관과 `intern.khu.ac.kr` 현장실습 사이트다. 기존 조사에서 본부 외부 링크 때문에 게시판 형식을 잘못 판단한 이력이 있다. 현재도 같은 상태인지는 원문으로 재확인한다.

1. 공식 공개 목록·상세·다음 페이지를 확인한다. 정상 0건과 추출 실패를 구별한다.
2. 같은 서버의 실제 게시판 구조, 번호, 날짜, 고정 여부, 본문, 첨부, 페이지 이동을 확인한다.
3. 기존 ListedItem(목록 항목), ListPage(목록 페이지), FetchedDetail(상세 결과) 계약에 맞춰 전용 추출기를 구현한다.
4. 공식 공개 자료 응답이나 피드가 있으면 더 효율적인 경로를 조사하되 실제 사용자 목록과 식별자 집합이 일치하는지 확인한다. 비공개·로그인 영역과 접근 제한을 우회하지 않는다.
5. 정상 목록, 둘째 페이지, 상세, 첨부, 빈 목록, 구조 오류를 재현 표본으로 남긴다. 날짜순 여부는 한 페이지의 날짜 최솟값만으로 확정하지 않는다.
6. 추출기 이름·설정·원문 주소·조직 연결·대표 표본·남은 한계를 보고한다. 등록부 반영은 제안만 한다.

통과 기준: 두 쪽 이상의 목록 번호를 정확히 구분하고, 서로 다른 상세 최소 3건에서 제목·날짜·본문·첨부가 원문과 일치한다. 게시판 하나만 확인한 것을 사이트 전체 지원이라고 보고하지 않는다.

## 우선순위 2 — 성격 미정 게시판 97개 판정

`board_profiles.json`에서 성격이 미정인 항목 전체를 대상으로 한다. 실제 현재 개수가 다르면 현재 수를 기록한다.

- 저장된 메뉴 경로·표본·판정 근거를 먼저 읽고, 필요한 후보만 원문 확인한다.
- 게시판 이름이나 제목의 '후기' 한 단어만으로 제외하지 않는다. 후기 입학·학위 관련 진짜 공지를 보존한다.
- 판정은 등록 후보·기존 출처와 통합·제외 후보·추가 확인 필요로 나눈다. 불명확한 항목을 억지로 확정하지 않는다.
- `registry/proposals/클로드_게시판_판정.json`에 항목별 원문 주소, 기존 식별 정보, 판정, 근거, 관찰 시각, 기존 출처와의 연결을 작성한다.
- 본부·학사·장학·취업 등 출시 영향이 큰 누락 후보를 먼저 보고한다. 등록 후보라고 바로 운영 활성화하지 않는다.

통과 기준: 대상 모든 항목에 근거와 처분이 남으며, 표본을 못 읽은 항목도 확인 필요로 기록한다. 중복 주소를 새 출처로 무작정 추가하지 않는다.

## 우선순위 3 — 누락 탐색과 반복 오류

앞 작업이 끝나면 탐색 미완료 호스트 13곳에서 중요 공지 경로부터 확인한다. 휴면 게시판 514개 전체 재조사보다 최근 공지가 실제로 빠진 출처를 우선한다. 대량 통신을 무작정 확대하지 않고 기존 표본을 활용한다.

삭제 표시 122건은 당시 운영 집계다. 클로드는 운영 DB를 직접 변경하지 않는다. Codex가 제공하는 후보 목록이 있을 때만 공식 원문 존재 여부와 추출 실패 이유를 조사한다. 자동 삭제·운영자 숨김·실제 원문 삭제를 구별하고 일괄 정상화하지 않는다.

## 금지 사항

- LLM이 없는 원문·게시일·첨부를 만들어 채우지 않는다.
- 원문 일부만 보고 3월 이후 전체 수집 완료라고 선언하지 않는다.
- 고정 공지를 일반 글 날짜 경계에 섞지 않는다.
- 접근 차단이나 구조 오류를 정상 0건으로 반환하지 않는다.
- 기존 공통 통신의 허용 호스트·사설 주소 차단을 해제하지 않는다.
- 실제 처리량 근거 없이 수십 배 가속이나 오전 8시 완수를 약속하지 않는다.

## 보고와 인계

첫 20~30분 안에 지원 가능 경로·막힌 이유·중요 누락 후보를 먼저 보고한다. 완성된 추출기는 전체 조사가 끝날 때까지 묶어 두지 말고 즉시 인계한다.

최종 보고에는 변경 파일, 실행한 검사와 결과, 확인한 원문 주소·건수, 등록부 제안 파일, 공통 코드에 필요한 통합 패치, 미검증 사항을 포함한다. 검사 실패를 숨기지 않는다. 최종 작업 결과는 `docs/클로드_수집예외_조사결과.md`에 저장한다.

클로드가 작성한 파일을 Codex가 검토한 뒤 등록·배포한다. 이 작업지시서 전달 자체가 클로드 작업을 실행했다는 뜻은 아니다.
